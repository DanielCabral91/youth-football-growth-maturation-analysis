# Methodology — Youth Football Growth & Maturation Analysis

## Purpose

This project reconstructs an exploratory analysis developed during a youth-football internship. Its purpose is to demonstrate a transparent data pipeline linking anthropometric data, standardisation, a rule-based growth-stage proxy and small-sample machine-learning evaluation.

## Processing steps

1. Load player data.
2. Validate required columns.
3. Compute decimal age and age in months at a fixed evaluation date.
4. Calculate BMI.
5. Join a height-for-age reference by age in months.
6. Estimate a height z-score using the internship approximation `(P97 - P3) / 4` as the standard deviation.
7. Calculate BMI z-scores through an LMS transformation.
8. Derive the exploratory labels `Pre-PHV proxy`, `PHV proxy` and `Post-PHV proxy` from height-z-score thresholds.
9. Evaluate an XGBoost classifier with Leave-One-Out Cross-Validation (LOOCV).
10. Export tables, metrics and visual outputs.

## Why LOOCV?

The original internship analysis had only 26 participants. A conventional train/test split would reserve a substantial fraction of an already small sample. LOOCV repeatedly trains on `n-1` observations and tests on the remaining observation, allowing every observation to contribute to evaluation.

LOOCV does not make a small dataset large, remove sampling uncertainty or validate the biological construct being predicted. It is an evaluation strategy chosen for data efficiency under a small-sample constraint.

## Target leakage correction

In the original exploratory code, `height_zscore` was both used to define the target category and included among the model predictors. The portfolio version removes `height_zscore` from the XGBoost feature set because that would constitute direct target leakage.

Even after this correction, the modelling task remains a reproduction exercise because the target itself is a derived proxy rather than an independently measured maturity outcome.

## Public-demo reference data

For reproducibility, the repository contains synthetic height and BMI reference tables. These files follow the schemas expected by the code but are not official WHO or clinical reference values. They should be treated only as software-demo fixtures.

An external validated reference source can be supplied through the CLI without changing the pipeline.

## Scientific limitation

A height-for-age z-score is not equivalent to a validated estimate of biological maturity or PHV timing. Therefore, the proxy labels generated by this project must not be interpreted as a clinical maturity diagnosis.

The project is presented as an example of data engineering, statistical reasoning, model evaluation and methodological self-critique in a youth-football context.
